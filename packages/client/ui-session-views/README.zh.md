# @deepseek-ai/dsh-client-ui-session-views

[English](README.md) | 中文

Session Views 向会话的 `'conversation.view'` slot 环贡献「文件」「任务」「瀑布」三个标签页。「文件」根据每次工具调用自身声明的意图推导出目录树——diff 卡片或 kind 为 `edit` 的通用卡片计为改动，read 卡片计为读取，search 卡片的结果计为搜索命中——因此该界面上没有任何内容来自模型叙述，也绝不会去猜测新建与覆盖的区别。「任务」把当前回合的待办清单放在首位，计划、目标与后台任务三个侧面置于其下；那里的每个数字都是整会话或实时的，来自宿主折叠的 projection，而非已加载窗口。「瀑布」把已加载窗口内的每个回合、步骤与工具调用绘制在同一条时间轴上，条形按百分比定位，因此缩放窗口不产生任何布局开销；它会区分仍在进行的跨度与边界事件已被翻页移出的跨度，并对无法定位的调用计数，而不是为它们虚构一个开始时间。该包不声明 service，也不声明 Context 合并：它只注册三个条目和一个 locale 命名空间，并通过标准 view kit 读取会话快照。让它独立成包而不是留在 ui-conversation 内部，正是上游那个包能与其发布版逐字节一致的原因；`'conversation.view'` 是 list slot，从外部注册只会新增席位，与 ui-trajectory 的做法完全相同。

## 模型体验

无。这些视图渲染的是浏览器中已有的会话数据；这里没有任何内容进入模型请求。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **文件树不显示「新建」标记**：新建与整文件覆盖在调用时都表现为 `FileDiff.oldText === null`，仅凭呈现意图无法区分，因此视图拒绝猜测究竟发生了哪一种。
- **「文件」与「瀑布」只覆盖已加载窗口**：两者都读取 `snapshot.chat`，因此翻页加载更早历史会改变它们的计数；界面用「仅已加载窗口」标签说明这一点，而不是让数字宣称它并不具备的完整性。
- **`isSettledTool` 与仅供读屏的样式规则是本地副本**：客户端 bundle 纯净性闸门禁止跨包的值导入，而 CSS module 没有公开子路径，因此两者都必须从 ui-conversation 复制，并靠评审而非编译器与其保持一致。
- **尚无行为测试**：三个视图迁移时没有带来测试，它们在上游同样没有；在客户端测试通道覆盖到它们之前，该包留在 GUI 覆盖率欠债豁免清单中。
